# cellward

*Прежнее имя — vpn-zones.* Команда — `cellward` (коротко `cw`; `vpn-zone`
по-прежнему работает, как и `vpn-zone-gui` вместо `cellward-gui`), опции —
`programs.cellward` и `services.cellward` (старые имена работают, с
предупреждением), а `github:TimSalguz/vpn-zones` ведёт сюда.

Read in English: [README.md](README.md) · План развития: [ROADMAP.md](ROADMAP.md)
· Устройство: [архитектура](docs/ARCHITECTURE.ru.md), [модель утечек](docs/LEAK-MODEL.md),
[системный уровень](docs/SYSTEM.md), [всё в контейнерах](docs/CONTAINERS.ru.md),
[ярлыки](docs/LAUNCHERS.ru.md), [сертификаты по контейнерам](docs/CERTIFICATES.ru.md),
[герметизация зоны](docs/HERMETICITY.ru.md)

Запуск программ с выбором сети, контейнера данных и песочницы — прямо из ярлыка
приложения. Пользовательский уровень работает целиком из-под пользователя: root
не нужен ни для создания зоны, ни для запуска, системную конфигурацию править не
требуется. Необязательный [системный уровень](#системный-уровень-по-желанию) —
модуль NixOS — держит зоны с загрузки для служб, NixOS-контейнеров и текстовой
консоли и умеет закрыть собственную сеть хоста всему, что вне зон.

Кликаешь по ярлыку — спрашивает, в какой сети запустить (через какой VPN, без
VPN или вообще без сети) и в каком окружении (общее с системой, отдельный
контейнер данных или песочница). Выбор запоминается, можно закрепить.

## Что оно делает

Три независимых слоя, каждый включается сам по себе.

**Сеть.** Зона — это сетевой namespace, поднятый из-под пользователя: внутри
туннель, наружу — `pasta` из passt. Туннель бывает двух видов: ядерный
WireGuard/AmneziaWG и OpenConnect (Cisco AnyConnect и ocserv, а через
`Protocol =` ещё GlobalProtect, Pulse, F5, Fortinet и Array). Зон может быть
сколько угодно, каждая со своим конфигом. Есть встроенные варианты
`unconfined` и `offline`. `unconfined` (до 2026-09 — `direct`, старое имя
по-прежнему работает) — сеть хоста, вокруг программы нет ничего от зоны: ни
VPN, ни своего резолвера, шина сеанса и `systemd --user` — хоста. `offline`
означает буквально отсутствие маршрута, а не правило файрвола.

Зоны **герметичны по умолчанию** (с 2026-09): у программы в зоне нет
`systemd --user`, а сессионная шина идёт через фильтр — порталы, уведомления,
значки трея, плееры и методы ввода проходят, запуск процесса вне зоны — нет.
Программа, которая открывает что-то в другой сети (ссылку, другую программу),
идёт через брокер: он спрашивает, в какой сети, и запоминает «Всегда» для
программы, которой ты доверяешь. `cellward hermetic <зона> off` возвращает зоне
сеанс хоста.

**Данные.** Пять режимов:

| режим | дом программы | кто видит |
|---|---|---|
| основной | твой настоящий `$HOME` | всё как обычно |
| контейнер | overlayfs поверх XDG-каталогов | видит твои настройки, пишет в слой |
| своя песочница | постоянный, только этой программы | ничего твоего |
| именованная песочница | постоянный, общий | программы, запущенные в ней |
| разовая песочница | tmpfs, стирается при выходе | ничего твоего |

Контейнер нужен в первую очередь чтобы развести singleton: без него браузер,
запущенный вторым, просто отдаёт окно уже работающему процессу — и трафик идёт
через старую сеть, а выглядит нормально.

**Изоляция.** Композитор умеет различать клиентов через
`wp_security_context_v1`: программам, запущенным через помеченный сокет, не
выдаются захват экрана, чтение буфера обмена в фоне, эмуляция клавиатуры и мыши,
список чужих окон. Замер до и после — 47 протоколов против 33.

Отдельно есть песочница файловой системы на `bwrap`: вместо `$HOME` пустой
каталог, шина через `xdg-dbus-proxy` (без Secret Service), а внутрь
подкладывается `/.flatpak-info` — по нему GTK/Qt/Chromium понимают, что они в
песочнице, и сами начинают ходить за файлами и камерой через порталы. Если
программе нужен X11, ей поднимается собственный `xwayland-satellite`, чтобы она
не видела чужие окна.

## Требования

- композитор с поддержкой `wp_security_context_v1` — проверено на **niri** и
  **KWin**; в Mutter (GNOME) протокола нет, слой изоляции композитора работать
  не будет;
- непривилегированные user namespace (`kernel.unprivileged_userns_clone`);
- диапазон в `/etc/subuid` и `/etc/subgid` для твоего пользователя — NixOS
  выдаёт их обычным пользователям по умолчанию;
- `/dev/net/tun` с доступом на чтение и запись (зоне OpenConnect больше ничего
  и не нужно — ни модуля ядра, ни root: клиент создаёт tun внутри собственного
  user namespace зоны);
- для WireGuard-зон — ядерный модуль `wireguard` или `amneziawg`;
- работающие XDG-порталы (для песочницы ФС).

Проверить готовность:

```sh
sysctl kernel.unprivileged_userns_clone   # 1
grep "^$USER:" /etc/subuid                 # диапазон есть
ls -l /dev/net/tun                         # crw-rw-rw-
```

## Поддерживаемые окружения

Бо́льшая часть проекта от рабочего стола не зависит вовсе: зоны и туннель, DNS,
контейнеры данных, песочница ФС со своим seccomp-фильтром, перехват
`.desktop`-ярлыков (freedesktop-стандарт) и порталы — годится любой бэкенд.
Зависят от него две вещи: слой композитора и диалоги.

| окружение | состояние |
|---|---|
| **Plasma 6, Wayland** | все слои, из коробки |
| **niri / sway / wlroots, Wayland** | все слои — основная площадка разработки |
| **GNOME, Wayland** | работает, кроме слоя композитора: в Mutter нет `wp_security_context_v1`, поэтому `wl-sandbox` запускает программу без ограничения и говорит об этом в stderr. Смягчает то, что Mutter и не раздаёт `wlr-screencopy`, `data-control`, `virtual-keyboard`, `foreign-toplevel` — того, от чего этот слой защищает, там по большей части нет. Диалоги Qt-шные, выглядят чужеродно |
| **любая X11-сессия** | сеть и файловая система изолированы, дисплей — НЕТ: хостовый X-сокет доступен изнутри зоны, а в общем X-сервере один клиент видит все окна, нажатия и буфер обмена машины. Не рекомендуется |
| **не NixOS** | логика та же, вопрос упаковки: nix плюс standalone home-manager (обычный пакет — в планах), непривилегированные userns (на Ubuntu 24.04 ещё и `sysctl kernel.apparmor_restrict_unprivileged_userns=0`), subuid/subgid и `amneziawg` через DKMS — либо ядерный `wireguard`, который поддержан как запасной путь |

Проверить композитор:

```sh
wayland-info | grep -i security_context   # протокол есть
```

Пикер спрашивает своим окном, `vpn-zone-window` (сеть и контейнер рядом,
управление с клавиатуры, светлая или тёмная — как в системе); остальные диалоги
— `kdialog`, его ставит сам модуль, так что KDE-сессия не нужна — нужен только
сам бинарь. Нет окна — пикер спрашивает `kdialog`'ом. Чтобы про
деградировавший слой говорил `cellward doctor`, а не только stderr, — в
планах.

## Установка

В NixOS — один импорт и одна строка:

```nix
{
  inputs.cellward.url = "github:TimSalguz/cellward";

  # в конфигурации NixOS
  imports = [ inputs.cellward.nixosModules.default ];
  programs.cellward.enable = true;
}
```

`programs.cellward.enable` включает то, что зонам от системы нужно в любом
случае, и ничего из того, что есть выбор:

- модули ядра, которые зона сама из непривилегированного user namespace не
  загрузит, — загружаются при старте: `amneziawg` (внешний, собирается под
  текущее ядро; `services.cellward.system.amneziawg = false` его не ставит, и
  тогда работают только конфиги без параметров обфускации, через ядерный
  `wireguard`), `wireguard`, `tun` и `nf_tables`;
- политику PipeWire для герметичных зон (`services.cellward.pipewirePolicy.enable`)
  — по умолчанию, если включён WirePlumber;
- если подключён модуль home-manager для NixOS — модуль home-manager каждому
  пользователю home-manager (`home-manager.sharedModules`), с
  `programs.cellward.enable` по умолчанию `true`; кому не нужно — `false`.
  Подключить ещё и `homeModules.default` самому не мешает;
- при системном уровне с политикой хоста (`system.enable`,
  `system.egress.enable`), если `system.host.nix` / `system.host.time` не
  заданы, — простую зону `direct0` (по умолчанию: своя `zones.direct0`
  сильнее), через которую выходят демон Nix и systemd-timesyncd. `host.time` —
  только при включённом timesyncd; `host.nix = null` оставляет демон в сети
  хоста.

Сам системный уровень, политика хоста и её режим, `host.dns`, пульт TTY, группа
выключателя и аварийный ключ остаются явным выбором.

Без NixOS или со standalone home-manager — как раньше:

```nix
{
  inputs.cellward.url = "github:TimSalguz/cellward";

  # в home-manager
  imports = [ inputs.cellward.homeModules.default ];
  programs.cellward.enable = true;
}
```

До переименования опции назывались `programs.vpn-zones.*` и
`services.vpn-zones.*`; старые имена работают и сейчас — через
`lib.mkRenamedOptionModule`, с предупреждением при каждом использовании.

После пересборки в лаунчере появятся пункты «Добавить VPN-зону», «Удалить
VPN-зону», «Оборвать VPN-зону», «Создать контейнер», «Удалить профиль
(контейнер)», «Контейнеры cellward» (окно со всеми контейнерами, их сетью,
программами и выданными каталогами), «Настройки cellward» и «Сбросить сети
программ».

То, что должно быть всегда, можно объявить, а не натыкать, — контейнеры, их сети
и программы, умолчания:

```nix
programs.cellward = {
  enable = true;
  defaults.network = "offline";              # незнакомой программе — без интернета
  containers.work = {
    home = "private";                        # свой дом
    network = "nl";                          # запуск в другой сети — отказ
    apps = [ "firefox" ];                    # запускается в нём без вопроса
    permissions.paths = [ "~/Downloads" ];
  };
  pathShims.enable = true;                   # набранное в терминале — тоже через пикер
};
```

`cellward status --json` показывает каждое значение и откуда оно (Nix, задано на
месте или умолчание).

Звук в герметичной зоне идёт через фильтр pulse (PulseAudio) и через свой
сокет PipeWire зоны, клиенты которого видят то, что им разрешает политика
WirePlumber из этого проекта: свои потоки, выходы, куда играть, микрофон —
только как скажет `cellward microphone`; никогда то, что играет хост, и
никогда чужой поток. `programs.cellward.enable` включает политику вместе с
WirePlumber; иначе она включается один раз:

```nix
services.cellward.pipewirePolicy.enable = true;  # NixOS: nixosModules.default
programs.cellward.pipewirePolicy = true;         # или home-manager без NixOS
programs.cellward.audioManager = [ "mixer" ];    # зона для pavucontrol/qpwgraph:
                                                 # сырой PipeWire хоста, громко
```

Без политики у герметичной зоны PipeWire нет вовсе — только путь PulseAudio,
которым пользуется большинство программ (`docs/LEAK-MODEL.md` §20).

Трансляция экрана идёт только через портал, и у неё тоже выключатель на зону:
`cellward screencast <зона> yes|no|ask|default`. `ask` (по умолчанию) — диалог
портала каждый раз, `no` — отказ, `yes` — выбор можно запомнить, если портал
знает зону по имени: фильтр шины называет порталу каждое соединение зоны
(`cellward.zone.<зона>`), и его диалоги говорят «cellward · <зона>», а не
«программа хоста» (`docs/LEAK-MODEL.md` §21, §23). Действует сразу; держит
фильтр шины герметичной зоны.

```nix
programs.cellward.microphone.calls = "ask";      # yes | no | ask
programs.cellward.screencast.calls = "yes";      # yes | no | ask
```

**Обновление не обрывает работающие зоны.** Переключение (home-manager или
`nixos-rebuild`) оставляет работающую зону, сокет брокера и туннель системной
зоны как есть: программы зоны не теряют сеть, а новые запуски уже идут через
новый `cellward`. Зона переходит на новую сборку, когда её перезапустят
(`cellward down <зона>; cellward up <зона>`), в удобный вам момент — до тех
пор исправления самого держателя к ней не применяются. Какие зоны остались на
прошлой сборке, видно в `cellward status --json` (`"build": "current" |
"previous"`) и в `cellward doctor`, а проверка туннелей один раз после
обновления об этом напоминает.

## Как пользоваться

Создать зону: ярлык **«Добавить VPN-зону»** → выбрать `.conf` → задать имя.
Система сама скажет, прошло ли рукопожатие, — то есть жив ли конфиг.

### Корпоративная зона: OpenConnect

Зону, в конфиге которой есть секция `[OpenConnect]`, несёт клиент
`openconnect`, а не ядерный туннель: Cisco AnyConnect и ocserv из коробки, а
через `Protocol =` ещё GlobalProtect, Pulse, F5, Fortinet и Array. Всё
остальное в зоне не меняется, и в этом весь смысл: корпоративный VPN живёт
внутри неё, RDP-клиент или браузер запускаются в ней, а хост и остальные
программы туннеля не видят.

Конфиг пишется руками и добавляется как любой другой (ярлык-«добавлялка» пока
рассчитан на `.conf` WireGuard-вида):

```ini
[OpenConnect]
Server     = vpn.example.com          ; хост или хост:порт — без схемы и пути
Protocol   = anyconnect               ; по умолчанию; nc | gp | pulse | f5 | fortinet | array
User       = alice
AuthGroup  = Employees                ; выпадающий список «realm»/«домен», если он есть
ServerCert = pin-sha256:HXXQ…=        ; пин сертификата; без него — системное хранилище CA
                                      ; (pin-sha256: или sha256: — но не sha1:)
PasswordFile = /home/alice/.config/vpn-zones/secrets/work.pass
MTU        = 1300                     ; необязательно, сильнее того, что предлагает шлюз
Args       = --no-dtls --os=linux-64  ; необязательно, только из белого списка
```

```sh
chmod 600 ~/.config/vpn-zones/secrets/work.pass   # обязательно, и это проверяется
cellward add work ~/work-vpn.conf
cellward up work && cellward run work -- remmina
```

Файл пароля остаётся там, куда его положили: `cellward rm` удаляет зону вместе
с её копией конфига, но никогда не трогает файлы вне каталога зоны. В отличие
от приватного ключа WireGuard, который лежит внутри конфига и уходит вместе с
зоной, этот файл остаётся на твоей совести.

#### Почему формат свой, а не родной

Родной способ записать настройки у `openconnect` есть, и даже два. Ни один из
них не годится на роль «конфига, который можно принять от кого-то»:

- **`--config=ФАЙЛ`** — это не описание VPN, а **командная строка, сложенная в
  файл**: «длинные опции, какие приняла бы командная строка, но без двух
  дефисов». В нём разрешено всё, в том числе `--script`, `--csd-wrapper`,
  `--external-browser` и `--no-system-trust`. Принять такой файл — значит
  принять заодно произвольную команду на запуск и произвольное решение о
  доверии;
- **`--xmlconfig=ФАЙЛ`** — XML-профиль AnyConnect, который раздаёт сам шлюз. Он
  описывает список шлюзов и политику клиента, учётных данных в нём нет, и
  зоной он не является: это дополнение к настройкам, а не они сами.

Поэтому секция `[OpenConnect]` — это **подмножество родных опций**, отобранное
так, чтобы файл нельзя было превратить в исполняемый. `Args` принимает только
белый список из пятнадцати флагов, и каждый обязан быть одним куском
`--флаг=значение`: разреши записать флаг и значение по отдельности, и
`Args = --useragent --script` протащил бы запрещённый флаг под видом значения
соседнего. Решение о доверии задаётся единственным способом — `ServerCert`.

#### Пароль: почему файл — и почему это ненадолго

`PasswordFile` существует по одной причине: зону поднимает systemd-юнит, у
которого нет терминала, поэтому клиент идёт с `--non-inter` — спрашивать не у
кого. Файл обязан быть `0600` и твоим, это проверяется и при `add`, и при
каждом подъёме, а содержимое читается один раз в аплинке прямо перед тем, как
уйти клиенту **на stdin**: класть его в `--passwd` нельзя, `/proc/<pid>/cmdline`
читает кто угодно.

Но правильное место для корпоративного пароля — ни файл, ни секрет,
зашифрованный ключом машины. Секрет вида sops машина расшифровывает **сама, без
человека, при каждой загрузке**: пароль сервиса так и надо хранить, а пароль
человека — нет. Он, как правило, тот же, что от домена и почты, и тогда кража
диска становится кражей учётной записи, причём второго фактора за ней не
остаётся. А где 2FA или одноразовый код, там хранить нечего вовсе: код живёт
полминуты.

Поэтому решение такое (ROADMAP M4): по умолчанию не хранить ничего и
спрашивать при подъёме — **своим окном, а не терминалом**, — сохраняя всё,
кроме пароля и одноразового кода; «запомнить пароль» — только в связку ключей
сеанса, которая открывается твоим входом в систему, а не загрузкой машины.
Показать вместо этого окно терминала с самим `openconnect`, который и так всё
спросит, было бы проще всего — но тогда зону поднимает человек, а не наш код,
и мимо проходят и пин сертификата, и белый список: ровно те две вещи, ради
которых формат свой.

`ServerCert` нужен, когда у шлюза корпоративный CA, которого система не знает;
шлюзу с публично доверенным сертификатом он не нужен вовсе. Сам `openconnect`
принимает ещё и `sha1:`-пин, а конфиг зоны — нет: пин и ЕСТЬ всё решение о
доверии, а SHA-1 давно не стойкий к коллизиям. Отпечаток спрашивается у самого
клиента — он печатает готовую строку `pin-sha256:`, и модуль кладёт его в
`PATH` ровно ради этого:

```sh
openconnect --non-inter vpn.example.com   # напечатает «--servercert pin-sha256:…»
```

Чего такая зона сознательно **не** делает — и всё по одной причине: зона
отправляет в туннель всё, и второго интерфейса, чтобы отправить остальное,
у неё нет (`docs/LEAK-MODEL.md`):

- **сплит-туннель.** Список сплит-маршрутов от шлюза игнорируется, количество
  пишется в журнал. Что шлюз делает с трафиком, о котором не просил, — не наша
  забота;
- **split-DNS.** Резолверы шлюза и его один домен по умолчанию попадают в
  `resolv.conf` зоны; резолвер «на домен» был бы вторым путём под другим именем;
- **IPv6** — не запрашивается вовсе (`--disable-ipv6`) и закрыт в зоне так же,
  как для WireGuard-конфига без v6-адреса;
- **интерактивная 2FA/OTP.** Зону поднимает systemd-юнит, спрашивать негде,
  поэтому клиент работает с `--non-inter`. Формат конфига этого не исключает
  (ROADMAP M4);
- **отключение проверки сертификата.** Его нечем записать: `ServerCert` обязан
  быть отпечатком, а `Args` — белый список, в котором нет ни
  `--no-system-trust`, ни `--allow-insecure-crypto`, ни `--script`, ни
  `--csd-wrapper`, ни `--external-browser`.

### Сеть через интерфейс хоста

У зоны, в конфиге которой есть секция `[HostInterface]`, своего туннеля нет:
её программы выходят через один интерфейс хоста — второй аплинк, модем, VPN,
поднятый самой системой, — и больше ни через что.

```ini
[HostInterface]
Interface = enp4s0
DNS = 192.168.1.1
```

Каждый сокет привязан к этому интерфейсу: интерфейс упал — зона без сети, а не
пошла в обход; интерфейса нет — зона не поднимается. Такая зона **ничего не
шифрует**: в `status --json` её тип — `host-interface`. Со стороны зоны адрес
`10.255.255.253/30`, какие бы адреса ни были у хоста.

Дальше просто запускай программы из лаунчера. Из терминала то же самое:

```sh
cellward add <зона> <файл.conf>                # зона из конфига AmneziaWG/WireGuard/OpenConnect
cellward add <зона> --system <системная зона>  # зона через туннель системной зоны
cellward list                                  # зоны и их состояние
cellward up <зона> / down <зона>
cellward check <зона>                          # жив ли туннель
cellward doctor [<зона>] [--json]              # что на деле закрыто — проверка изнутри зоны
cellward journal [--json] [<N>]                # запуски без ограничений и решения брокера
cellward kill <зона>                           # оборвать зону сейчас: программы убиты, зона опущена
cellward container grant sb:<имя> <каталог> [--for 2h]  # каталог своему дому, на время
cellward watch [--json]                        # живы ли туннели (зовёт таймер, уведомляет)
cellward status --bar                          # строка JSON для waybar и подобных баров
cellward focused [--json|--bar|--watch]        # зона и контейнер окна в фокусе (niri, sway)
cellward window-menu                           # его меню: закрепить сеть, перезапустить с выбором, закрыть, оборвать
cellward launch <id> [-- арг.]                 # ярлык через пикер (для биндов)
cellward run <зона> -- firefox                 # запустить в зоне
cellward run <зона> --profile work -- firefox  # + контейнер данных
cellward run <зона> --sandbox work -- firefox  # + именованная песочница
cellward run <зона> --fs-sandbox -- firefox    # + разовая песочница
cellward run <зона> --tmp-profile -- firefox   # одноразовый контейнер

cellward profile create|list|rm <имя>
cellward sandbox create|list|rm <имя>
cellward perms list|reset <программа|--all>    # выданные доступы к файлам
cellward lock|unlock <зона>                    # запретить выход в другие сети
cellward x11 <зона> on|off                     # свой X-сервер программам зоны
cellward hermetic <зона> on|off|default        # без systemd --user, шина через фильтр, брокер
cellward hermetic --default on|off             # для зон без своей настройки (вкл. с 2026-09)
cellward default-profile ask|main|own|<имя>
cellward mode picker|per-zone|both|off         # как ведут себя ярлыки (per-zone, both — устарели)
cellward default offline|unconfined|<зона>     # что пикер предлагает незнакомой программе
cellward pins / forget <программа|--all>       # закреплённые за сетями программы и снять закрепление
cellward container list|show|set|assign|merge  # контейнеры: сеть, программы, X11, объединение двух
cellward trust add|list|rm <контейнер> …       # корневой сертификат только для одного контейнера
```

**В какой зоне это окно.** Меню окна в фокусе — на клавишу композитора, его зону
— в панель. С home-manager часть композитора пишет модуль:

```nix
programs.cellward.desktop = {
  windowMenu.key = "Mod+Shift+Z";   # запись niri; null — без клавиши
  floatWindows = true;              # окно запуска и меню плавающие (по умолчанию)
  niri.enable = true;               # ~/.config/niri/vpn-zones.kdl
  niri.includeInConfig = true;      # дописать `include "vpn-zones.kdl"` в config.kdl,
                                    # который home-manager пишет текстом
  sway.enable = true;               # ~/.config/sway/vpn-zones.conf (модуль sway
                                    # из home-manager подключит сам)
};
```

Без home-manager — то же руками:

```kdl
// niri, config.kdl
binds {
    Mod+Shift+Z { spawn "cellward" "window-menu"; }
}
// окно запуска и меню — плавающие, а не отдельной колонкой
window-rule {
    match app-id="^vpn-zone-window$"
    open-floating true
}
```

Подключённый файл читается там, где стоит его `include`: в конце config.kdl он
перекрывает привязку той же клавиши выше.

```jsonc
// waybar: строка при каждой смене фокуса, класс по зоне — чтобы красить
"custom/cellward": { "exec": "cellward focused --watch", "return-type": "json" }
```

Сеть окна — сетевое пространство его собственного процесса (pid композитор
знает от ядра), сверенное с хостом и зонами; контейнер — от ближайшего запуска
вверх по родителям, если этот запуск точно ещё жив (его время старта записано)
и в той же сети. Программа, отцепившаяся от своего запуска, показывает сеть, а
контейнер — «не известен». Заголовку окна ничего не доверяется; строка для
панели экранирует разметку.

## Системный уровень (по желанию)

Всё, что выше, — пользовательский уровень: сеанс, твой пользователь, без root.
Системный уровень — модуль NixOS поверх него: зоны, которые держит systemd с
загрузки, для того, у чего сеанса нет:

- **службы и NixOS-контейнеры в зоне** (`services.<юнит>.zone`,
  `containers.<имя>.zone`): служба получает пространство и resolv.conf зоны, а
  nscd, resolved и системная шина от неё спрятаны;
- **простые зоны** (`kind = "plain"`): без туннеля, наружу через сеть хоста
  через pasta — «напрямую», но всё равно своё пространство без ничего от хоста;
- **собственные службы хоста через зону**: загрузки демона Nix (`host.nix`),
  часы (`host.time`), имена самого хоста (`host.dns`);
- **политика хоста** (`egress`): `audit` пишет в журнал, какие программы вне
  всех зон ходили в сеть, `enforce` их отрезает, `strict` ещё и root с
  системными пользователями держит в локальной сети — что должно дальше, идёт
  через зону;
- **один VPN — одно подключение**: у пользовательской зоны может не быть своего
  туннеля, она идёт через туннель системной (`cellward add <имя> --system <зона>`);
- **пульт в TTY** (`console`): вход в текстовой консоли попадает в меню, где сеть
  уже есть, — терминал в VPN-зоне, простая зона про запас, если VPN не поднялся;
- **выключатель**: `vpn-zones-off` возвращает всё в сеть хоста без пересборки и
  без сети и переживает перезагрузку; `vpn-zones-on` — обратно.

```nix
# NixOS
imports = [ inputs.cellward.nixosModules.default ];
programs.cellward.enable = true;     # с политикой хоста: простая зона direct0 для nix и часов
services.cellward.system = {
  enable = true;
  users = [ "alice" ];               # видят состояние зон и добавляют зоны на месте
  egress = { enable = true; mode = "audit"; };   # сперва наблюдать, потом enforce
};
```

То же без единой точки входа — и так же демон Nix или часы отправляются в
другую зону — пишется явно: `zones.direct0.kind = "plain";` («напрямую»),
`host.nix = "direct0";`, `host.time = "direct0";`.

```sh
vpn-zone-sys <зона> -- <команда>          # консольная программа в системной зоне (users зоны)
vpn-zone-sys --add <зона> <файл.conf>     # системная зона на месте (system.users)
vpn-zones-off / vpn-zones-on              # всё выключить (wheel, пароль) и включить обратно
systemctl start vpn-zones-egress-open     # снять политику хоста на 15 минут (wheel)
```

Ключ зоны в Nix не попадает никогда: `configFile` называет файл во время работы
(расшифрованный секрет, например), либо конфиг кладётся в
`/var/lib/vpn-zones/system/<зона>/`. Что он делает, чего не делает и все
решения по дороге: [docs/SYSTEM.md](docs/SYSTEM.md).

## Чего это не заменяет

Flatpak. Его фильтр системных вызовов — образец для здешнего, и вдобавок у него
свой рантайм и готовые правила на тысячи приложений. Здесь пакеты
берутся из nixpkgs (никакого дублирования и рантайма), но правила под каждую
программу выясняются самостоятельно — впрочем, их можно подсмотреть в манифесте
той же программы на Flathub, в секции `finish-args`.

Чего здесь нет и что стоит знать:

- seccomp-фильтр в песочнице теперь есть — по образцу базового набора flatpak
  (вставка в терминал через `TIOCSTI`, `ptrace`, keyring, `perf_event_open`,
  новый mount-API); вложенные user namespace намеренно оставлены разрешёнными,
  иначе не стартуют Chromium и Electron-программы;
- песочница файловой системы включается явно и требует доводки под конкретную
  программу;
- зона изолирует сеть, но не файлы: без песочницы программа видит весь `$HOME`;
- проверено на одной машине и одном наборе программ.

## Как это устроено внутри

Тонкости, на которые ушло больше всего времени, подробно закомментированы в
`module/default.nix`. Самые неочевидные:

- зона — это **два** сетевых namespace, а не один: связность (pasta и UDP-сокет
  туннеля) живёт в шлюзовом, а в том, где работают программы, нет ничего, кроме
  loopback и туннеля — утечь там некуда физически, каким бы ни было семейство
  протоколов (`docs/LEAK-MODEL.md`). Интерфейс создаётся в шлюзовом и
  переезжает вниз: сокет WireGuard остаётся в том namespace, где интерфейс
  родился;
- зона **OpenConnect** — та же стена, только за ней стоит другое: в шлюзовом
  namespace остаётся целиком процесс клиента вместе с TLS-сессией и адресом
  шлюза, а вниз переезжает голый tun. Устройство tun и открытый на него
  дескриптор — разные вещи, поэтому клиент продолжает читать и писать пакеты
  после того, как интерфейс ушёл из его namespace; а создать этот tun без root
  он может потому, что `TUNSETIFF` спрашивает `CAP_NET_ADMIN` у владельца
  сетевого namespace, а владелец — наш собственный user namespace;
- поверх этой топологии, и только как страховка от нашей же ошибки, в обоих
  namespace стоит **фильтр nftables**: из зоны приложений наружу ничего, кроме
  туннеля, из шлюзового — ничего, кроме пакетов самого туннеля до сервера. Ядро,
  которое его не приняло, стоит предупреждения в журнале, а не зоны: основную
  нагрузку несёт топология;
- держателю зоны нужен **двойной маппинг uid**: `0:<subuid>:1` (иначе
  capabilities теряются при `execve` и интерфейс не создать) плюс
  `<uid>:<uid>:1` (иначе программа не видит свой `$HOME`);
- `upperdir` overlayfs не может лежать на overlayfs — отсюда раздельные каталоги
  хранения;
- `mount(8)` не работает не от root даже при наличии `CAP_SYS_ADMIN`, поэтому
  монтирование идёт прямым вызовом `libc.mount`;
- за именами glibc ходит к демону по **unix-сокету**, которого не остановить
  ни маршрутом, ни фаерволлом: в NixOS работает `nsncd`, а при включённом
  `systemd-resolved` спрашивают в первую очередь его (`resolve` в
  `nsswitch.conf` стоит перед `dns`). Оба сокета в зоне прячутся — без этого
  имена резолвятся мимо туннеля, и leak-тест называет твоего настоящего
  провайдера;
- конфиги Amnezia приходят в CRLF, а свежие ещё и с пустыми параметрами
  `I1`–`I5`, на которых `awg setconf` отвергает файл целиком;
- фильтр сессионной шины — `xdg-dbus-proxy` с одной маленькой нашей правкой
  (`module/patches/`): шаблоны у него бывают только вида `org.kde.*`, а значок
  трея Electron или Qt должен занять `org.kde.StatusNotifierItem-<pid>-<n>` —
  занять всё `org.kde.*` значило бы занять и имя KWallet, поэтому
  `--own=ИМЯ-*` занимает этот префикс и больше ничего;
- службы системного уровня входят в зону через генератор systemd, а не через
  свои юнит-файлы — поэтому `vpn-zones-off` возвращает их в сеть хоста без
  пересборки; политика хоста различает программы по владельцу сокета в
  nftables. Разрешения добавляются поверх таблицы, которую `nft` грузит сам, —
  поэтому сбой нашего кода оставляет хост закрытее; таблица, которая не
  загрузилась вовсе, — упавший юнит, и хост такой же, как без политики
  (`docs/SYSTEM.md`).
