# Всё по умолчанию в контейнерах (M8) — дизайн

English: [CONTAINERS.md](CONTAINERS.md) · Связанные документы:
[LAUNCHERS.ru.md](LAUNCHERS.ru.md) (ярлыки), [CERTIFICATES.ru.md](CERTIFICATES.ru.md)
(доверие по контейнерам), [LEAK-MODEL.md](LEAK-MODEL.md), [GOTCHAS.md](GOTCHAS.md)

**Статус: дизайн принят с решениями владельца от 2026-09-17 (§12).** Всё, что
названо здесь «новым», ещё не существует, если не помечено «сделано».

## 1. Коротко

Сегодня запуск — это три независимых выбора на каждый клик: сеть (зона,
direct, offline), контейнер данных (основной, профиль-оверлей, одноразовый) и
песочница файловой системы (нет, своя, именованная, разовая). Дизайн сводит
три оси в одну сущность — **контейнер**:

> Контейнер — это именованная личность: дом, набор разрешений, набор доверенных
> сертификатов **и одна сеть в каждый момент**. Экземпляр программы работает
> ровно в одном контейнере. Программы назначаются контейнерам, сети — тоже
> контейнерам, и оба назначения можно менять когда угодно — явно, а не побочным
> эффектом клика.

Следствия, по важности:

1. **Личность меняет сеть, только когда человек так решил**
   ([LEAK-MODEL](LEAK-MODEL.md), «Открытые каналы» §4). Вопрос о сети на каждый
   клик — ровно то, чем один профиль браузера незаметно уезжал в две сети;
   смена сети теперь отдельное действие и так и показывается.
2. **Ни один слой не теряется молча.** Любой запуск идёт одной дорогой — в зону,
   в `direct` или в `offline`. Баг с `direct`, исправленный в `fix/launch-path`
   (пикер терял контейнер, песочницу и ограничение композитора), — ровно тот
   класс, который так исключается по построению.
3. **У каждой программы по умолчанию свой дом**, а два контейнера можно
   объединить в один (§3.4).
4. **Запуски мимо лаунчера попадают в нужный контейнер**: D-Bus-активация,
   автозапуск, бинды композитора, ссылки из других программ, записи, которые
   программы пишут в пользовательский каталог (§5).
5. **Ярлыки на каждую зону объявлены устаревшими**; их заменяет вид по
   контейнерам ([LAUNCHERS.ru.md](LAUNCHERS.ru.md) §4).
6. **Всё декларативно** через опции home-manager-модуля, а машиночитаемое
   состояние говорит, откуда взято каждое значение (§8, §9).

## 2. Что есть сегодня

| понятие | где живёт | что изолирует |
|---|---|---|
| зона | `~/.local/state/vpn-zones/<зона>/` + `vpn-zone@<зона>` | сеть (в app-ns только `lo` и туннель); WireGuard, AmneziaWG или OpenConnect |
| `direct` | нигде | ничего (сеть хоста) |
| `offline` | зона с маркером, создаётся по требованию | всё сетевое, включая резолверы хоста |
| контейнер-оверлей («профиль») | `~/.local/state/vpn-profiles/<имя>/` | XDG-каталоги (`.config`, `.local/share`, `.cache`, `.mozilla`, `.pki`) |
| одноразовый контейнер | `/tmp/vpn-profile-*` | то же, стирается за последним жильцом |
| именованная песочница | `~/.local/state/vpn-sandboxes/<имя>/{home,perms}` | весь дом, шина, runtime-каталог, seccomp, X11 |
| своя песочница программы | именованная песочница `app-<ключ>` | то же |
| разовая песочница | tmpfs | то же, стирается при выходе |
| ограничение композитора | `wl-sandbox`, включено по умолчанию | захват экрана, эмуляция ввода, фоновый буфер обмена |

Пикер помнит всё по программе: `.pinned`/`.last` (сеть) и
`.pinnedprofile`/`.lastprofile` (контейнер). Оси независимы — и именно поэтому
личность одной программы может переезжать между сетями.

## 3. Модель

### 3.1 Контейнер

```
контейнер = {
  имя          уникальное; селектор — тот, что уже пишет реестр
  дом          private | overlay | throwaway-private | throwaway-overlay
  сеть         одна сеть (§3.3) или ask
  маршруты     дополнительные именованные маршруты рядом с сетью (LAN, …) — выключены
  разрешения   файлы {downloads, documents, pictures, home, paths[]}, x11,
               композитор {restricted | full}, (позже) имена шины, устройства
  доверие      дополнительные корневые сертификаты (CERTIFICATES.ru.md)
  программы    назначенные сюда (id ярлыков)
  источник     nix (только чтение) | local (CLI/GUI)
}
```

- **`дом`** один в один ложится на то, что есть: `private` — сегодняшняя
  именованная песочница (и своя `app-<ключ>`), `overlay` — сегодняшний профиль,
  одноразовые виды — сегодняшние `--fs-sandbox` и `--tmp-profile`. Каталоги
  данных остаются на местах: это часть контракта ([GOTCHAS](GOTCHAS.md) §5).
- **`разрешения.paths`** выдают отдельному дому конкретные каталоги настоящего,
  биндом по тому же пути: `~/.wine` программе Wine, библиотеку Steam — Steam.
  Без этого умолчание «свой дом» ломает ровно те программы, что живут данными в
  общем доме (§3.5).
- **`сеть = ask`** — значение совместимости: сеть спрашивается при каждом
  запуске, как сейчас. Существующие контейнеры мигрируют в него.
- **Основной дом — не контейнер.** «Без контейнера» остаётся (системные
  утилиты, терминал с `sudo`), так и называется и не может держать доверия.

### 3.2 Инварианты

- **I1. Одна сеть в каждый момент; смена — явная.** Контейнер запускается
  только в свою текущую сеть. Смена сети — отдельное действие: «Сменить сеть
  контейнера…» в пикере и GUI, `vpn-zone container set <c> network <сеть>` в
  терминале, опция в Nix — и никогда не побочный эффект выбора, где запустить
  программу. `vpn-zone run <другая> --profile <c>` — отказ с названным выходом,
  а не молчаливый запуск.
- **I2. Работающие программы сохраняют свою сеть.** Процесс нельзя перенести в
  другую сеть (§7). Пока программы контейнера работают в сети A, в сети B он не
  запускается; смена сети предлагает закрыть их и перезапустить.
- **I3. Один контейнер на экземпляр программы.** Реестр пишет селектор;
  проверка конфликта смотрит ещё и на бинарь (сделано).
- **I4. Все слои на любой дороге.** Сеть, дом, разрешения, доверие и
  ограничение композитора накладывает один путь кода (`vpn-zone run` →
  `entry_argv` → `profile-run`) для любого вида сети (сделано для зон,
  `direct` и `offline`).
- **I5. Незнакомое — без сети.** Программа без назначения стартует без сети,
  пока её не дали ([GOTCHAS](GOTCHAS.md) §2), в своём доме
  (`defaults.container = own`).
- **I6. Отказ вместо деградации.** Контейнер, чьей сети больше нет, где-то ещё
  не стартует; слой доверия, который не удалось наложить, останавливает запуск
  ([CERTIFICATES.ru.md](CERTIFICATES.ru.md) §4).

### 3.3 Чем может быть сеть

| вид | как | root |
|---|---|---|
| зона: WireGuard/AmneziaWG | ядерный туннель создаётся в аплинке и переезжает в app-ns (сделано) | нет |
| зона: OpenConnect | клиент в аплинке, его tun переезжает в app-ns (сделано) | нет |
| зона: другой клиент (sing-box, OpenVPN, GUI-клиент) | та же схема, M4 | нет |
| через интерфейс хоста | аплинк, где pasta привязана к этому интерфейсу (`--outbound-if4/-if6`): второй аплинк, модем, VPN, поднятый системой | нет |
| `direct` | сеть хоста, без namespace (сделано) | нет |
| `offline` | только loopback (сделано) | нет |
| **сам** интерфейс хоста внутри контейнера | перенос настоящего линка в чужой netns требует `CAP_NET_ADMIN` в namespace хоста | **да**: маленький системный помощник (опция NixOS-модуля), никогда не по умолчанию |

**Дополнительные маршруты** (`маршруты`) стоят рядом с единственной сетью —
типичный пример LAN рядом с туннелем. Каждый — именованное явное исключение:
правило в аплинке плюс маршрут в app-ns ровно на этот префикс, по умолчанию
выключены и видны в любом отображении контейнера. Второго маршрута по умолчанию
не бывает никогда: два выхода — это утечка, ждущая ошибки маршрутизации.

### 3.4 Объединение двух контейнеров

`vpn-zone container merge <из> <в>` (и пункт в GUI): для программ, которым
оказалось по пути (браузер и менеджер паролей).

- программы контейнера `<из>` назначаются в `<в>`;
- дом `<из>` копируется в `<в>` **только там, где у `<в>` такого пути нет**;
  конфликтующие пути уходят в каталог `.merged-from-<из>/` дома `<в>` и
  перечисляются — сливать два профиля браузера инструмент решать не может;
- сеть остаётся от `<в>`; сертификаты доверия объединяются (диалог ⚠ из
  [CERTIFICATES.ru.md](CERTIFICATES.ru.md) показывается для каждого нового для
  `<в>` сертификата); разрешения `<из>`, которых нет у `<в>`, спрашиваются, а
  не копируются;
- `<из>` сохраняется, уже без программ, пока его не удалят руками;
- отказ, пока работают программы любого из двух контейнеров (I2).

### 3.5 Свой дом и его цена

`own` по умолчанию означает, что неназначенная программа стартует в пустом
отдельном доме. Программы, ждущие свои данные в общем доме, их не найдут:

| программа | что ей нужно | как она это получает |
|---|---|---|
| программы Wine | префикс (`~/.wine` или `WINEPREFIX` из ярлыка) | префикс берётся из `Exec` записи и предлагается как `разрешения.paths` при первом запуске |
| Steam | `~/.local/share/Steam`, `~/.steam` | подсказка для известной программы, предлагается при первом запуске |
| программы, которые человек уже настроил в общем доме | их настройки | диалог первого запуска предлагает «свой дом», «слой над домом» (overlay) и «без контейнера» |

Подсказки — список в крейте, где каждая запись называет программу и пути;
ничего не выдаётся без ответа человека.

### 3.6 Устройство одного запуска (порядок — это и есть спецификация)

```
[nsenter -U -n -m -t <зона>]  или  [unshare -U --map-current-user --keep-caps]   (direct)
  └─ unshare --mount --propagation private           когда что-то монтируется
      └─ vpn-zone-core profile-run --cwd <каталог> …   (сделано)
           1. дом: слоты оверлея или бинды для разрешения.paths
           2. герметичность runtime (§6, этап 4): tmpfs поверх /run/user/<uid>,
              сокеты возвращаются поимённо; tmpfs поверх /tmp/.X11-unix
           3. доверие: бинды бандла, базы NSS (CERTIFICATES.ru.md)
           4. chdir <каталог> → $HOME → /          (сделано)
           5. сброс ambient capabilities
           6. exec: wl-sandbox → fs-sandbox (bwrap) → программа
```

Всё монтируется в собственном mount namespace запуска, никогда — в namespace
зоны: два контейнера одной зоны не должны видеть слоёв и сертификатов друг
друга. bwrap биндит рекурсивно, поэтому песочница видит то, что смонтировали
шаги 1–3.

## 4. Выбор контейнера

Порядок для запуска программы `P`:

1. работающий экземпляр `P` (по id ярлыка): тот же контейнер — клик по
   запущенной программе означает «разверни окно» ([GOTCHAS](GOTCHAS.md) §11);
2. назначение из Nix (`programs.vpn-zones.containers.<c>.apps`);
3. локальное назначение (сделанное в пикере);
4. `defaults.container`: `own` — новый отдельный контейнер с именем программы,
   сеть `offline` и один вопрос: какую сеть ему дать (то же меню, что сейчас,
   ответ запоминается как сеть контейнера).

Пикер показывает контейнер и его сеть и никогда не спрашивает сеть у
назначенной программы:

```
«Firefox» — контейнер firefox · VPN nl · свой дом
  ▶ Запустить
  ⇄ Сменить сеть контейнера…         (I1: явно; работающие программы перезапустятся)
  ⧉ Другой контейнер…                (список контейнеров с их сетями)
  ⊕ Объединить с другим контейнером…
  Разово: одноразовый контейнер, без сети
```

Для контейнеров `ask` и для «без контейнера» сегодняшний диалог «сначала
сеть» остаётся — ничего, на что человек полагается сейчас, не пропадает.

## 5. Запуски мимо лаунчера

Перехват — это **маршрутизация по умолчанию, а не граница безопасности**.
Процесс на хосте всегда может сделать `exec` пути в store напрямую; пользователь
хоста доверенный. Граница проходит в направлении «контейнер → наружу» (§6).

| путь | сегодня | дизайн | этап |
|---|---|---|---|
| ярлык в лаунчере (меню, fuzzel/rofi, KRunner, noctalia) | теневой ярлык пикера в `~/.local/share/applications` | без изменений; пикер «сначала контейнер» | 1 |
| скрытые обработчики (`NoDisplay=true` + `MimeType`) | **сделано**: перехватываются под id видимой записи той же программы | — | 0 |
| записи-дети (`steam steam://rungameid/…`) | **сделано**: без клонов, запуск под id клиента | к ним добавляются веб-приложения браузера (`--app-id=`) | 0/3 |
| записи, которые программы пишут в пользовательский каталог (игры Steam, `userapp-*`, веб-приложения, Wine) | не перехватываются: чужие файлы не переписываются | перехват на месте с резервной копией и повторный перехват после перезаписи ([LAUNCHERS.ru.md](LAUNCHERS.ru.md) §3.2); инвариант меняется отдельным коммитом | 3 |
| `xdg-open`, `gio open`, `kde-open`, «открыть с помощью» | находят `.desktop` → теневой ярлык | без изменений | — |
| D-Bus-активация (`gapplication launch`, `DBusActivatable=true`) | service-файл активирует мимо тени | теневые сессионные service-файлы в `$XDG_DATA_HOME/dbus-1/services/<id>.service` только для перехваченных id; никогда для порталов и системных имён | 3 |
| автозапуск XDG | стартует без контейнера | назначенные программы стартуют в своём контейнере; **неназначенные — без сети, в своём доме, без диалога, и об этом приходит уведомление** | 3 |
| бинды композитора | только если бинд зовёт `vpn-zone-pick` | `vpn-zone launch <id-ярлыка>` берёт `Exec` из записи; опция модуля отдаёт командную строку | 3 |
| шелл | без контейнера | по желанию — PATH-шимы для назначенных программ; границей не являются | 3 |
| портал `OpenURI` из программы хоста | портал → запись обработчика → тень → пикер | без изменений | — |
| портал `OpenURI` из контейнера | происхождение теряется | брокер (§6.2) | 4 |
| ссылка, открытая изнутри зоны | делегируется через `systemd --user` | та же дверь, но с охраной: брокер | 4 |
| `systemd-run --user`, `systemctl --user` изнутри зоны | доступны | герметичность runtime (§6.1) | 4 |
| `flatpak-spawn --host` | выходит через сессионную шину | у отдельных домов шина уже отфильтрована; оверлеи — с §6.1 | 4 |
| программы, запущенные другими программами хоста | без контейнера | вне рамок (хост доверенный); `doctor` это называет | — |

### 5.1 Команда запуска для биндов

`vpn-zone launch <id-ярлыка> [-- доп. аргументы]` находит запись по id в тех же
каталогах, что читает `sync`, берёт её `Exec` (коды полей — из доп.
аргументов) и становится пикером для неё:

```kdl
Mod+B { spawn "vpn-zone" "launch" "firefox"; }
```

## 6. Граница наружу (этап 4)

Это пункты M3; контейнеры превращают их в умолчания контейнера.

### 6.1 Герметичность runtime

В mount namespace запуска: tmpfs поверх `/run/user/<uid>`, назад биндами —
только сокет Wayland (уже ограниченный), PipeWire, PulseAudio и сокет брокера;
tmpfs поверх `/tmp/.X11-unix` плюс `unset DISPLAY` ([LEAK-MODEL](LEAK-MODEL.md)
§7), а программам с разрешением `x11` — свой `xwayland-satellite` контейнера;
по выбору tmpfs поверх `/run/dbus`. Отдельные дома всё это уже получают через
bwrap; оверлеи — когда появится брокер.

### 6.2 Брокер

По сокету на контейнер, в его runtime-каталоге. Один глагол: «открой это» (URI,
файл, переданный дескриптором, или id ярлыка). Сторона хоста знает
контейнер-источник:

- программа назначена **тому же** контейнеру → запуск там же, без диалога;
- контейнер заперт → только тот же контейнер;
- иначе → пикер, с источником в вопросе.

Входы изнутри контейнера: `xdg-open`/`$BROWSER` указывают на клиента брокера;
делегирование в `launch.rs` (шаг 1) идёт в брокер; порталы перестают получать
`OpenURI`/`OpenFile` через прокси шины (правила `--call` по интерфейсам
порталов). GTK, Qt и Firefox под `/.flatpak-info` зовут портал и на `xdg-open`
не откатываются, поэтому сначала нужен совместимый с порталом фронт для
`OpenURI`. **Открытый вопрос исследования**, прототип в VM прежде любых
обещаний.

## 7. Границы возможного без root

- **Нет глобального перехвата `exec`.** События разрешений fanotify, хуки LSM и
  eBPF требуют `CAP_SYS_ADMIN`/`CAP_BPF` в исходном user namespace. seccomp
  user notification потребовал бы `NO_NEW_PRIVS` на всю сессию, что ломает все
  setuid-помощники (`sudo` и `newuidmap`, на котором стоят зоны), и всё равно не
  достаёт до детей `systemd --user`.
- **Нет сетевой политики по процессам на хосте.** cgroup BPF и `net_cls`
  требуют root. Сеть — это всегда namespace.
- **Работающий процесс нельзя перенести** в другую сеть или контейнер; `setns`
  действует на вызывающего (I2).
- **Интерфейс хоста нельзя перенести в контейнер** без `CAP_NET_ADMIN` в
  сетевом namespace хоста (§3.3). Трафик *через* него — можно без root; *сам*
  интерфейс внутри — только системным помощником.
- **Файлы хоста не меняются — меняется только их вид**, а точка монтирования
  обязана уже существовать: внутри каталогов root ничего не создать.
- **Сессионную шину хоста нельзя отфильтровать для программ хоста** — только
  для контейнеров, через прокси.
- **Модули ядра** (`amneziawg`, `nf_tables`) из user namespace не грузятся, а
  `/etc/subuid` один раз требует администратора.
- **Программам со встроенным доверием или своим runtime** (Flatpak,
  pressure-vessel Steam, AppImage, `webpki-roots`) слой доверия снаружи не дать
  ([CERTIFICATES.ru.md](CERTIFICATES.ru.md) §2).
- **Записи в собственном каталоге приложений пользователя** перехватываются
  только перезаписью, и программа, переписывающая свою запись, выигрывает на
  мгновение — до повторного перехвата ([LAUNCHERS.ru.md](LAUNCHERS.ru.md) §3.2).

## 8. Декларативная конфигурация (опции home-manager-модуля)

Опции принадлежат **home-manager**-модулю (`homeModules.default`) и задаются в
домашней конфигурации того пользователя, к которому относятся; в NixOS-модуле
их нет. Декларативные значения пишутся в `~/.config/vpn-zones/declared/` этого
пользователя (ссылки в store, только чтение) и сильнее локального состояния;
CLI и GUI показывают их как «задано в Nix» и отказываются менять.

```nix
programs.vpn-zones = {
  enable = true;

  launcher.mode = "picker";              # picker | per-zone (устарел) | both (устарел) | off
  defaults = {
    network = "offline";                 # offline | direct | <сеть>
    container = "own";                   # own | ask | main | <контейнер>
  };
  compositorRestriction.enable = true;

  networks.lan-uplink = {                # зоны локальны (ключи); это вид без root
    kind = "host-interface";
    interface = "enp4s0";
  };

  containers.work = {
    home = "private";                    # private | overlay
    network = "nl";                      # <зона> | <сеть> | direct | offline | "ask"
    routes = [ ];                        # например [ "192.168.1.0/24" ] — явные дыры
    apps = [ "firefox" "org.telegram.desktop" ];
    permissions = {
      filesystem = [ "downloads" ];      # downloads | documents | pictures | home
      paths = [ ];                       # например [ "~/.wine" ]
      x11 = false;
    };
    trust = {                            # CERTIFICATES.ru.md
      certificates = [ ./certs/some-root-ca.pem ];
      acknowledgeRisk = true;            # обязательно при непустом certificates
    };
  };

  autostart.unassigned = "offline";      # offline (без диалога, с уведомлением) | as-is
  interception = {
    dbusActivation = true;
    userEntries = "take-over";           # take-over | leave — LAUNCHERS.ru.md §3.2
  };
};
```

- Сами зоны не декларируются: конфиг зоны — это приватный ключ, в Nix store ему
  не место никогда. Декларативный контейнер, названный на несуществующую сеть, —
  отказ при запуске (I6), а не ошибка вычисления.
- Проверки: непустой `trust.certificates` требует `acknowledgeRisk`; одна
  программа в `apps` двух контейнеров — ошибка; `permissions.filesystem` или
  `paths` у дома `overlay` — предупреждение (не применяются).

## 9. Машиночитаемое состояние

`vpn-zone status --json` печатает всё; `vpn-zone container list --json` и
`vpn-zone container show <имя> --json` — подмножества той же схемы.

- **`schema_version`** есть в каждом документе. В пределах версии изменения
  только добавляющие; удаление поля или смена его смысла — новая версия и запись
  в CHANGELOG.
- **У каждого настраиваемого значения указано происхождение**: `{"value": …,
  "source": "nix" | "local" | "default"}`. Факты времени выполнения (`running`,
  `up`, `handshake_age_s`) — простые значения.

```json
{
  "schema_version": 1,
  "defaults": {
    "network":   { "value": "offline", "source": "default" },
    "container": { "value": "own",     "source": "nix" },

    "compositor_restriction": { "value": true, "source": "default" }
  },
  "networks": [
    { "name": "nl", "kind": "amneziawg", "source": "local",
      "up": true, "locked": false, "handshake_age_s": 42 }
  ],
  "containers": [
    { "name": "work", "selector": "sb:work",
      "home":    { "value": "private", "source": "nix" },
      "network": { "value": "nl",      "source": "local" },
      "routes":  { "value": [],        "source": "default" },
      "apps":    [ { "value": "firefox", "source": "nix" } ],
      "permissions": {
        "filesystem": { "value": ["downloads"], "source": "nix" },
        "paths":      { "value": [],            "source": "default" },
        "x11":        { "value": false,         "source": "default" },
        "compositor": { "value": "restricted",  "source": "default" }
      },
```

## 10. Куда теперь может уйти пакет или DNS-запрос мимо туннеля?

- **Меняемые сети (I1, I2).** Смена явная и видимая; контейнер никогда не
  работает в двух сетях сразу. Канал личности из [LEAK-MODEL](LEAK-MODEL.md) §4
  сужен до сознательного действия.
- **Сети через интерфейс хоста.** Аплинк привязан к одному интерфейсу; app-ns —
  тот же двухлинковый namespace, что и для туннеля, поэтому изнутри другой выход
  не выбрать. Чего такая сеть не делает — не шифрует; так она и называется
  везде, где показана.
- **Дополнительные маршруты.** Каждый — дыра по определению: явная, по
  префиксу, выключена по умолчанию, видна в любом отображении и в `doctor`.
- **Контейнеры в `direct`** (сделано). Сетевого namespace нет — сеть и резолверы
  хоста, и так и названо. User namespace прав над netns хоста не даёт.
- **Mount namespace запуска, выдача путей.** Сеть не меняется.
- **`vpn-zone launch`, шимы, тени автозапуска и D-Bus, перехваченные записи.**
  Только запускают пикер или `vpn-zone run`; ни нового сокета, ни маршрута.
- **Брокер.** Дверь с охраной вместо неохраняемого пути через `systemd --user`.
- **Вывод JSON.** Называет зоны и контейнеры процессам пользователя; внутри
  отдельного дома каталога состояния не видно вовсе.
- **Слой доверия.** Канал MITM со своим разбором:
  [CERTIFICATES.ru.md](CERTIFICATES.ru.md) §5.

## 12. Решения владельца (2026-09-17)

1. **Сети и контейнеры меняются независимо**, и сетью контейнера может быть
   любой интерфейс, а не только зоны проекта → I1/I2 (явная смена, двух сетей
   сразу не бывает), §3.3 (интерфейсы хоста — без root через pasta; сам
   интерфейс внутри — только системным помощником), дополнительные маршруты как
   явные дыры.
2. **У каждой программы свой дом, с возможностью объединения** →
   `defaults.container = own`, §3.4, §3.5.
3. **Всё в контейнерах, включая записи в пользовательском каталоге** → перехват
   на месте с резервной копией ([LAUNCHERS.ru.md](LAUNCHERS.ru.md) §3.2, с ценой и
   риском по видам записей); инвариант меняется отдельным коммитом.
4. **Неназначенный автозапуск: без сети, без диалога, с уведомлением** → §5.
5. **Ярлыки на каждую зону объявлены устаревшими сейчас** →
   [LAUNCHERS.ru.md](LAUNCHERS.ru.md) §4.
6. **`feat/openconnect-backend` влита первой** → сделано.
