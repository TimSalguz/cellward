# Проверка ввода разрешений и сетевых правил

## Ввод

Выбор сети задаёт маршрут контейнера. Отдельный вопрос о сети программы
разрешает новые соединения. Выбор VPN сам по себе не отвечает на этот вопрос.

Раньше обе кнопки встроенной панели требовали паузы после наведения указателя.
Ранний щелчок начинал ожидание заново, без видимого объяснения. Обычные повторные
щелчки могли постоянно оставлять кнопки неработающими.

Теперь «Разрешить…» обычным нажатием и отпусканием открывает отдельный
защищённый вопрос. Сам посредник по-прежнему не может разрешить доступ.
Постоянный отказ сохраняет ожидание при наведении и защиту от всплывающих окон
программы. В отдельном окне остаются требование фокуса клавиатуры и паузы перед
принятием ответа.

Если панель не ответила за 15 секунд, надзиратель снимает её и передаёт вопрос
защищённому окну. В ответе сохраняется исходный Wayland-дисплей, даже если
окружение systemd хранителя его не знает или называет другой. Поздний ответ
снятой панели не засчитывается. Цикл надзирателя может добавить до двух секунд;
общий настроенный срок вопроса сохраняется, поэтому более короткий срок может
закончиться раньше перехода.

Через общий надзиратель это работает для сети, микрофона и камеры. Закрытие
окончательного вопроса оставляет доступ запрещённым. Сам переход ничего не
разрешает, не записывает правило разрешения и не продлевает общий срок.

## Сетевые правила

Перед отпуском ожидающих соединений и записью разрешения ответ сверяется
с текущими правилами. Новый запрет сильнее разрешающего ответа на старый вопрос.

Оставшиеся ограничения, найденные при проверке:

- `relay::gated` задерживает TCP/UDP, кроме DNS к пересыльщику экземпляра;
  кадры других протоколов тоже исключены. Запрет программе не равнозначен сети
  offline. Существующие слова вопроса «сети нет» обещают больше этого правила.
  Полную сетевую изоляцию даёт пространство offline. Чтобы убрать исключение
  DNS, нужны определение программы для DNS-запросов и отдельные тесты утечек.
- Ответ без постоянного правила запоминается до завершения экземпляра
  контейнера. Закрытие одной программы может его не завершить. Явное правило
  проверяется раньше этого ответа для новых соединений; удаление правила
  не сбрасывает уже запомненный временный ответ.
  Для известной программы `cellward container net <контейнер> allow <программа>`
  явно разрешает новые соединения; `<программа>` — id ярлыка. Это адресный способ
  восстановить доступ при уже застрявшем сеансе, если более строгий запрет
  в Nix этому не препятствует. Выбранный маршрут контейнера не меняется.
- Неопределённые программы сейчас имеют общий ключ `None` в обработчике
  вопросов. Временный ответ одной может затронуть другие неопределённые
  программы того же экземпляра. Эти правила не изолируют программы внутри
  одного контейнера друг от друга; для такой границы нужны разные контейнеры.
- Новые правила применяются к новым соединениям и не разрывают уже разрешённые.
  Исправление запоздалого ответа дополнительно проверяет соединения, которые
  ещё ждали решения.

## Регрессионные проверки

Rust-тесты проверяют немедленное открытие защищённого вопроса, сохранение
защиты отказа, правильного дисплея при переходе и нового запрета при открытом
старом вопросе. `tests/vm-niri.nix` проверяет настоящий ввод указателя через
вложенный niri, обе кнопки панели, переход без ответа и реальный TCP-запрос
ко второй VM: до разрешения он не должен достигать HTTP-сервера, после явного
разрешения должен, при закрытии вопроса должен остаться заблокированным.
Существующий тест панели на sway также проверяет обычный щелчок перехода.

Скриншоты передаются через консоль гостя: при повторном копировании через 9p
под TCG наблюдалось падение ядра гостя в сборщике записей netfs.
