· Спецификация прошлых граблей: [GOTCHAS.md](GOTCHAS.md) §10, §10a, §11, §13

**Статус (2026-09-17):** §2 — разбор сегодняшнего кода; фиксы с пометкой
*сделано* лежат в ветке `fix/launch-path` (CI зелёный), остальное —

## 1. Как это работает сегодня

### 1.1 Генерация (`rust/src/desktop.rs`, `vpn-zone-core sync`)

1. **Источники**, по приоритету: `~/.local/share/applications`,
   `/etc/profiles/per-user/<пользователь>/share/applications`,
   `/run/current-system/sw/share/applications`, затем каждый
   `$XDG_DATA_DIRS/applications`. Из одноимённых файлов побеждает первый.
2. **Кандидаты**: `Type=Application` с непустым `Exec`, не
   `NoDisplay`/`Hidden`, имя не `vpn-zone-*`, нет ключа `X-VPNZone`.
3. **Режим picker** (по умолчанию): для каждого кандидата из системного каталога
   в `~/.local/share/applications` пишется файл **с тем же именем** и затеняет
   системный (правило приоритета XDG). Копия сохраняет все ключи, включая
   `MimeType` и коды полей; `Exec` становится `vpn-zone-pick --id <имя файла без
   .desktop> -- <исходный Exec>`; добавляются `DBusActivatable=false` и
   `X-VPNZone=picker`, `TryExec` выбрасывается. Человекочитаемое имя идёт в
   `~/.local/state/vpn-zones/.labels/<id>` — в `Exec` его нет, потому что
   некоторые лаунчеры режут `Exec` по пробелам, не снимая кавычек.
4. **Режим per-zone**: для каждого кандидата (включая пользовательский каталог)
   и каждой зоны — `vpn-zone-<зона>-<имя>.desktop` с `Name=… (<зона>)`,
   `Exec=vpn-zone run <зона> -- <Exec без кодов полей>` и без `MimeType`.
   `both` делает и то, и другое.
5. **Уборка**: наши файлы (маркер есть, не симлинк), которые этот проход не
   породил, удаляются. Чужие файлы и симлинки не трогаются никогда; файл
   пишется, только если изменилось содержимое (за каталогом следит path-юнит).
6. **Триггеры**: активация home-manager, таймер (через 2 минуты после входа,
   затем каждые 30 минут), path-юнит на три главных каталога-источника,
   `vpn-zone mode`/`rm`.

### 1.2 Цепочка запуска

```
лаунчер → vpn-zone-pick --id K -- cmd
  память: работающий экземпляр (.running) → закрепление (.pinned/.pinnedprofile)
          → прошлый выбор (.last/.lastprofile) → умолчания
  диалоги: сеть, затем (по запросу или при закреплённой сети и свободном
           контейнере) контейнер
  → vpn-zone run <сеть> [--profile P | --tmp-profile [--join D]]
                        [--sandbox S | --fs-sandbox] -- cmd
      делегирование наружу / замок → контейнер → обёртки
      (wl-sandbox, fs-sandbox) → предупреждение о конфликте → подъём зоны
      → реестр → exec: nsenter | unshare → profile-run → программа
```

## 2. Найденные проблемы

| № | проблема | последствие | статус |
|---|---|---|---|
| L1 | **«direct» шёл мимо `vpn-zone run`**: пикер сам становился командой | выбранный/закреплённый/заданный по умолчанию контейнер или песочница терялись (весь `$HOME`), не было ограничения Wayland и записи в реестре, замок запертой зоны обходился | **сделано** |
| L2 | `nsenter` делает `chdir("/")` | терминал, запущенный в зоне, открывается в `/` (§10a) | **сделано** |
| L3 | ключ конфликта — id ярлыка **или** бинарь | две записи на один однопроцессный бинарь (игра Steam и Steam, firefox и firefox-private) не предупреждали; для передачи ссылки текст был не тот (§10a) | **сделано** |
| L4 | `VPN_ZONE_DELEGATED` оставался в окружении программы | вторая ссылка, нажатая в программе, открытой через делегирование, падала в `nsenter` | **сделано** |
| L5 | записи-дети (`Exec=steam steam://rungameid/…`) считаются программами | режим per-zone: клоны «игры × зоны» (около сотни на реальном рабочем столе), и каждый обещает выбор сети, который клиент проигнорирует (§10a) | следующая ветка |
| L6 | **записи с `NoDisplay=true` не перехватываются никогда** | обработчики ссылок и файлов — это как раз записи, спрятанные из меню (`x-scheme-handler/…`, помощники «открыть с помощью»): ссылка, открытая через такую запись, запускает программу без контейнера, мимо пикера. На реальном рабочем столе таких обработчиков схем в системных каталогах десять | следующая ветка: перехватывать `NoDisplay`-записи с `MimeType` (сохраняя `NoDisplay`) |
| L7 | **чужие записи в `~/.local/share/applications` не перехватываются никогда** | игры Steam, веб-приложения браузеров, Wine, всё созданное через портал DynamicLauncher — и записи `userapp-*`, которые программы пишут, делая себя обработчиком по умолчанию. На реальном рабочем столе `mimeapps.list` отправляет `http`, `https` и `tg` именно в такие записи: **любая ссылка из любой программы хоста запускает браузер (или мессенджер) без контейнера, в прямой сети**, хотя системная запись той же программы перехвачена | решение владельца (§3.2); самый весомый пункт таблицы |
| L8 | id санитизируется с потерями (`[A-Za-z0-9._-]`, остальное → `_`) | два не-ASCII имени записи одинаковой длины совпадают (`Игра.desktop`, `Мода.desktop` → `____`): общие закрепления, метки, реестр и дом песочницы — одна программа стартует в сети или контейнере другой | предложение: при потерях дописывать короткий хеш; старые ключи мигрировать один раз |
| L9 | у клонов per-zone нет id ярлыка | разрешения песочницы и реестр — по бинарю, не так, как в режиме пикера (грабля «два набора доступов у Discord», §6); `Desktop Action` теряются | неактуально, если клоны объявить устаревшими (§4) |
| L10 | D-Bus-активация обходит тень | `DBusActivatable=false` помогает только лаунчерам, которые его уважают; service-файл программы всё равно её активирует (`gapplication launch`, «открыть с помощью» в GNOME) | этап 3 ([CONTAINERS.ru.md](CONTAINERS.ru.md) §5) |
| L11 | автозапуск не перехватывается | программы из `~/.config/autostart` или `/etc/xdg/autostart` стартуют при входе без контейнера | этап 3 |
| L12 | метка берётся из непереведённого `Name` | диалоги говорят «Firefox» там, где меню пишет локализованное имя | M6 |

Path-юнит к тому же не следит за каталогами из `$XDG_DATA_DIRS` (экспорты
Flatpak): новые приложения Flatpak подхватит таймер, до 30 минут спустя.
Мелочь; записано, чтобы не открывать заново.

## 3. Предлагаемые исправления

### 3.1 Записи-дети (L5)

Запись — ребёнок, если аргумент её `Exec` — URL, схему которого объявляет
(`MimeType=x-scheme-handler/<схема>`) **другой** кандидат, запускающий ту же
программу (то же первое слово команды после обёрток). Steam: у `steam.desktop`
`Exec=steam %U` и `x-scheme-handler/steam`; у каждой игры
`Exec=steam steam://rungameid/<id>`.

- режим per-zone: детям клонов нет (уборка снесёт существующие);
- режим пикера, когда ребёнка можно перехватить: `--id <id родителя>`, чтобы
  клик направляла запись работающего клиента и действовала проверка конфликта;
- меню остаётся честным: игра работает в контейнере клиента, и интерфейс
  говорит «контейнер Steam», а не предлагает сеть на каждую игру.

### 3.2 Чужие записи в пользовательском каталоге (L7) — нужно решение

Сегодняшний инвариант: **чужие файлы в `~/.local/share/applications` не
переписываются никогда** ([GOTCHAS](GOTCHAS.md) §10). Он появился, потому что
первый же sync, его нарушивший, стёр записи, которые туда кладёт Nix. Трюк с
тенью здесь не помогает: каталога с приоритетом выше этого нет.

| вариант | что даёт | риск |
|---|---|---|
| A. оставить (как сейчас) | эти программы остаются без контейнера | дыра в «всё в контейнерах» — и обработчиком ссылок браузера по умолчанию может оказаться как раз такая запись |
| B. перехватывать на месте **(рекомендуется)** | обычной (не симлинк) чужой записи `Exec` оборачивается так же, как в тени, и ставится `X-VPNZone=adopted`; исходные байты хранятся в `~/.local/state/vpn-zones/.adopted/<имя>` и возвращаются при `mode off` или когда программа исчезает | программы, переписывающие свою запись (некоторые мессенджеры — при каждом старте), отменяют перехват до следующего sync, который path-юнит запустит сразу; симлинки (home-manager) не трогаются |
| C. спрятать и скопировать | в оригинале `Hidden=true`, рядом `vpn-zone-user-<имя>` | чужой файл всё равно меняется, и ссылки `mimeapps.list` на исходное имя ломаются |

Направить `mimeapps.list` на перехваченную запись — тоже не решение: этот файл —
состояние человека, а не конфигурация. Там живут его собственные «всегда
открывать этим», и программы переписывают его всякий раз, делая себя
обработчиком по умолчанию, — перехват обязан работать при любом его текущем
содержимом.

Вариант B меняет записанный инвариант, поэтому он придёт отдельным коммитом с
обоснованием и за опцией `interception.userEntries = "take-over"` (по
умолчанию `leave`, пока владелец не решит).

### 3.3 Обработчики с `NoDisplay` (L6)

В режиме пикера перехватывать записи `NoDisplay=true`, у которых есть
`MimeType`, и сохранять `NoDisplay=true` в тени. `Hidden=true` по-прежнему
исключается (это «удалено»). Клонов per-zone для них нет.

### 3.4 id с потерями (L8)

`ключ = sanitize(имя)`, если ничего не потеряно, иначе `sanitize(имя) + "-" +
первые 8 шестнадцатеричных цифр хеша имени`. При первом запуске под новым
ключом пикер переносит `.pinned`, `.pinnedprofile`, `.last`, `.lastprofile` и
`.labels` со старого ключа, если на него отображается ровно одна запись; при
коллизии неоднозначная память сбрасывается и вопрос задаётся заново. Дома
песочниц `app-<старый ключ>` переименовываются так же.

## 4. Что будет с ярлыками

Мысль владельца: если каждая программа живёт в контейнере, а у каждого
контейнера своя сеть, ярлыки на каждую зону больше не нужны. Оценка:

- **Клоны на каждую зону противоречат модели контейнеров.** Весь их смысл —
  «эта программа, в той сети», то есть ровно тот выбор, который отнимает
  [CONTAINERS.ru.md](CONTAINERS.ru.md) I1, потому что так одна личность
  оказывается в двух сетях. К тому же они растут как программы × зоны: около
  сотни на реальном рабочем столе, и большинство — игры, которые этот выбор
  всё равно не выполнят (L5).
- **Один перехваченный ярлык остаётся.** Это и есть механизм «контейнеров по
  умолчанию»: всё, что запускает программу через её запись (меню, `xdg-open`,
  обработчики, а после этапа 3 — бинды и автозапуск), идёт через пикер, и пикер
  без диалога находит контейнер, как только программа назначена.
- **Где клоны действительно нужны, их заменяют ярлыки контейнеров.** Только для
  программы, назначенной двум и более контейнерам («Firefox — work», «Firefox —
  personal»), по назначениям, а не произведением. `Exec=vpn-zone launch <id>
  --container <c>`; `MimeType` — только у основной записи программы, как сейчас.

**Предложение** (ничего пока не удаляется):

1. сейчас: исправить L5 и L6; `mode per-zone`/`both` печатают в `vpn-zone mode`
   и `sync` предупреждение об устаревании;
2. с моделью контейнеров (этап 1): ярлыки контейнеров для программ, назначенных
   нескольким; настройки GUI перестают предлагать `per-zone`;
3. после того как владелец подтвердит, что вид по контейнерам покрывает его
   сценарии: убрать генерацию per-zone, с записью в CHANGELOG и миграцией,
   удаляющей наши клоны (они наши: маркер на месте).
