## 1. Как это работает сегодня

### 1.1 Генерация (`rust/src/desktop.rs`, `vpn-zone-core sync`)

1. **Источники**, по приоритету: `~/.local/share/applications`,
   `/etc/profiles/per-user/<пользователь>/share/applications`,
   `/run/current-system/sw/share/applications`, затем каждый
   `$XDG_DATA_DIRS/applications`. Из одноимённых файлов побеждает первый.
2. **Кандидаты**: `Type=Application` с непустым `Exec`, не
   `NoDisplay`/`Hidden`, имя не `vpn-zone-*`, нет ключа `X-VPNZone`.
3. **Режим picker** (по умолчанию): для каждого кандидата из системного каталога
   в `~/.local/share/applications` пишется файл **с тем же именем** и затеняет
   системный (правило приоритета XDG). Копия сохраняет все ключи, включая
   `MimeType` и коды полей; `Exec` становится `vpn-zone-pick --id <имя файла без
   .desktop> -- <исходный Exec>`; добавляются `DBusActivatable=false` и
   `X-VPNZone=picker`, `TryExec` выбрасывается. Человекочитаемое имя идёт в
   `~/.local/state/vpn-zones/.labels/<id>` — в `Exec` его нет, потому что
   некоторые лаунчеры режут `Exec` по пробелам, не снимая кавычек.
4. **Режим per-zone**: для каждого кандидата (включая пользовательский каталог)
   и каждой зоны — `vpn-zone-<зона>-<имя>.desktop` с `Name=… (<зона>)`,
   `Exec=vpn-zone run <зона> -- <Exec без кодов полей>` и без `MimeType`.
   `both` делает и то, и другое.
5. **Уборка**: наши файлы (маркер есть, не симлинк), которые этот проход не
   породил, удаляются. Чужие файлы и симлинки не трогаются никогда; файл
   пишется, только если изменилось содержимое (за каталогом следит path-юнит).
6. **Триггеры**: активация home-manager, таймер (через 2 минуты после входа,
   затем каждые 30 минут), path-юнит на три главных каталога-источника,
   `vpn-zone mode`/`rm`.

### 1.2 Цепочка запуска

```
лаунчер → vpn-zone-pick --id K -- cmd
  память: работающий экземпляр (.running) → закрепление (.pinned/.pinnedprofile)
          → прошлый выбор (.last/.lastprofile) → умолчания
  диалоги: сеть, затем (по запросу или при закреплённой сети и свободном
           контейнере) контейнер
  → vpn-zone run <сеть> [--profile P | --tmp-profile [--join D]]
                        [--sandbox S | --fs-sandbox] -- cmd
      делегирование наружу / замок → контейнер → обёртки
      (wl-sandbox, fs-sandbox) → предупреждение о конфликте → подъём зоны
      → реестр → exec: nsenter | unshare → profile-run → программа
```

## 2. Найденные проблемы

| № | проблема | последствие | статус |
|---|---|---|---|
| L1 | **«direct» шёл мимо `vpn-zone run`**: пикер сам становился командой | выбранный/закреплённый/заданный по умолчанию контейнер или песочница терялись (весь `$HOME`), не было ограничения Wayland и записи в реестре, замок запертой зоны обходился | **сделано** |
| L2 | `nsenter` делает `chdir("/")` | терминал, запущенный в зоне, открывается в `/` (§1) | **сделано** |
| L3 | ключ конфликта — id ярлыка **или** бинарь | две записи на один однопроцессный бинарь (игра Steam и Steam, firefox и firefox-private) не предупреждали; для передачи ссылки текст был не тот (§5) | **сделано** |
| L4 | `VPN_ZONE_DELEGATED` оставался в окружении программы | вторая ссылка, нажатая в программе, открытой через делегирование, падала в `nsenter` | **сделано** |
| L5 | записи-дети (`Exec=steam steam://rungameid/…`) считаются программами | режим per-zone: клоны «игры × зоны» (около сотни на реальном рабочем столе), и каждый обещает выбор сети, который клиент проигнорирует (§10) | **сделано** |
| L6 | **записи с `NoDisplay=true` не перехватываются никогда** | обработчики ссылок и файлов — это как раз записи, спрятанные из меню (`x-scheme-handler/…`, помощники «открыть с помощью»): ссылка, открытая через такую запись, запускает программу без контейнера, мимо пикера. На реальном рабочем столе таких обработчиков схем в системных каталогах десять | **сделано**: перехватываются под id видимой записи той же программы; помощники без неё не трогаются |
| L7 | **чужие записи в `~/.local/share/applications` не перехватываются никогда** | игры Steam, веб-приложения браузеров, Wine, всё созданное через портал DynamicLauncher — и записи `userapp-*`, которые программы пишут, делая себя обработчиком по умолчанию. На реальном рабочем столе `mimeapps.list` отправляет `http`, `https` и `tg` именно в такие записи: **любая ссылка из любой программы хоста запускает браузер (или мессенджер) без контейнера, в прямой сети**, хотя системная запись той же программы перехвачена | **сделано**: перехват на месте с сохранённым оригиналом (§3.2); самый весомый пункт таблицы |
| L8 | id санитизируется с потерями (`[A-Za-z0-9._-]`, остальное → `_`) | два не-ASCII имени записи одинаковой длины совпадают (`Игра.desktop`, `Мода.desktop` → `____`): общие закрепления, метки, реестр и дом песочницы — одна программа стартует в сети или контейнере другой | предложение: при потерях дописывать короткий хеш; старые ключи мигрировать один раз |
| L9 | у клонов per-zone нет id ярлыка | разрешения песочницы и реестр — по бинарю, не так, как в режиме пикера (грабля «два набора доступов у Discord», §6); `Desktop Action` теряются | неактуально, если клоны объявить устаревшими (§4) |
| L10 | D-Bus-активация обходит тень | `DBusActivatable=false` помогает только лаунчерам, которые его уважают; service-файл программы всё равно её активирует (`gapplication launch`, «открыть с помощью» в GNOME) | этап 3 ([CONTAINERS.ru.md](CONTAINERS.ru.md) §5) |
| L11 | автозапуск не перехватывается | программы из `~/.config/autostart` или `/etc/xdg/autostart` стартуют при входе без контейнера | этап 3 |
| L12 | метка берётся из непереведённого `Name` | диалоги говорят «Firefox» там, где меню пишет локализованное имя | M6 |

Path-юнит к тому же не следит за каталогами из `$XDG_DATA_DIRS` (экспорты
Flatpak): новые приложения Flatpak подхватит таймер, до 30 минут спустя.
Мелочь; записано, чтобы не открывать заново.

## 3. Предлагаемые исправления

### 3.1 Записи-дети (L5)

Запись — ребёнок, если аргумент её `Exec` — URL, схему которого объявляет
(`MimeType=x-scheme-handler/<схема>`) **другой** кандидат, запускающий ту же
программу (то же первое слово команды после обёрток). Steam: у `steam.desktop`
`Exec=steam %U` и `x-scheme-handler/steam`; у каждой игры
`Exec=steam steam://rungameid/<id>`.

- режим per-zone: детям клонов нет (уборка снесёт существующие);
- режим пикера, когда ребёнка можно перехватить: `--id <id родителя>`, чтобы
  клик направляла запись работающего клиента и действовала проверка конфликта;
- меню остаётся честным: игра работает в контейнере клиента, и интерфейс
  говорит «контейнер Steam», а не предлагает сеть на каждую игру.

### 3.2 Чужие записи в пользовательском каталоге (L7) — перехват

**Решение (владелец, 2026-09-17): всё в контейнерах, включая эти записи.**
Сегодняшний инвариант — чужие файлы в `~/.local/share/applications` не
переписываются никогда ([GOTCHAS](GOTCHAS.md) §10); он появился, потому что
первый же sync, его нарушивший, стёр записи, которые туда кладёт Nix. Трюк с
тенью не помогает: каталога с приоритетом выше этого нет. Направить
`mimeapps.list` на перехваченную запись — тоже не решение: этот файл —
состояние человека, а не конфигурация. Там живут его собственные «всегда
открывать этим», и программы переписывают его всякий раз, делая себя
обработчиком по умолчанию.

**Способ: перехват на месте, оригинал сохраняется, повторный перехват после
перезаписи.**

1. Кандидат — **обычный файл** (никогда не симлинк: записи home-manager и Nix
   не трогаются), не наш, с пригодным `Exec`.
2. Его точные байты сохраняются в `~/.local/state/vpn-zones/.adopted/<имя>`
   вместе с хешем переписанной версии.
3. Запись переписывается так же, как тень (`Exec` через пикер,
   `DBusActivatable=false`, `X-VPNZone=adopted`), остальное сохраняется.
4. За каталогом уже следит path-юнит: когда программа снова пишет свою запись,
   файл перестаёт совпадать с сохранённым хешем, новые байты заменяют
   сохранённый оригинал, и запись перехватывается заново.
5. `vpn-zone mode off`, удаление программы или `interception.userEntries =
   "leave"` возвращают каждый оригинал байт в байт.

| вид записи | кто и когда её пишет | как перехватывается | цена и остаточный риск |
|---|---|---|---|
| игры Steam (`Exec=steam steam://rungameid/…`) | Steam, при создании ярлыка | ребёнок: запуск под id Steam, без клонов | переписываются редко; пока Steam работает, игра всё равно окажется в контейнере Steam (FIFO в общем доме) |
| веб-приложения браузера (`chromium --app-id=…`, `--profile-directory=`) | браузер, при установке и обновлении | ребёнок браузера (открывает тот же однопроцессный браузер) | переписываются при обновлениях браузера; между перезаписью и повторным перехватом (сильно меньше секунды, path-юнит) клик запустил бы без контейнера |
| `userapp-*` мессенджеров и браузеров, ставших обработчиками по умолчанию | сама программа, **при каждом старте** | свой id ярлыка, если у программы нет видимой записи, иначе id программы | самая частая перезапись. Каждый старт программы снимает перехват до повторного перехвата path-юнитом; ссылка, нажатая в это окно, открылась бы без контейнера. Если программа в этот момент уже работает, ссылка уйдёт в работающий экземпляр. Приемлемо только с повторным перехватом; записано, а `doctor` показывает число повторных перехватов |
| Wine (`wine-extension-*`, `wine-protocol-*`, записи программ) | `winemenubuilder`, при каждом обновлении префикса | свой id; путь префикса из `WINEPREFIX=` в `Exec` предлагается как выдача пути | отдельный дом без префикса не запустит программу вовсе — отсюда выдача пути; много мелких записей на префикс |
| записи, написанные человеком руками | человек | как любая запись | меняется его собственный файл; оригинал сохранён, `leave` его вернёт |

Перехват — это **изменение записанного инварианта**, и он пришёл отдельным
коммитом с этим обоснованием. **Сделано**: по умолчанию `take-over`, выключается
`interception.userEntries = "leave"` (или файлом `user-entries` со словом
`leave`), покрыт юнит-тестами и подтестом VM.

### 3.3 Обработчики с `NoDisplay` (L6)

Сделано. В режиме пикера записи `NoDisplay=true` с `MimeType` перехватываются
под id видимой записи той же программы и сохраняют `NoDisplay=true` в тени;
клонов нет. Скрытая запись без видимой записи своей программы — системный
помощник (OAuth-колбэк, обработчик URL настроек), и он не трогается: перехват
поставил бы диалог выбора сети посреди входа в аккаунт. `Hidden=true`
по-прежнему исключается (это «удалено»).

### 3.4 id с потерями (L8)

`ключ = sanitize(имя)`, если ничего не потеряно, иначе `sanitize(имя) + "-" +
первые 8 шестнадцатеричных цифр хеша имени`. При первом запуске под новым
ключом пикер переносит `.pinned`, `.pinnedprofile`, `.last`, `.lastprofile` и
`.labels` со старого ключа, если на него отображается ровно одна запись; при
коллизии неоднозначная память сбрасывается и вопрос задаётся заново. Дома
песочниц `app-<старый ключ>` переименовываются так же.

## 4. Что будет с ярлыками

Мысль владельца: если каждая программа живёт в контейнере со своей сетью,
ярлыки на каждую зону больше не нужны. Оценка и решение (владелец, 2026-09-17:
**объявить устаревшими сейчас**):

- **Клоны на каждую зону противоречат модели контейнеров.** Весь их смысл —
  «эта программа, в той сети», то есть выбор сети на каждый клик, которым одна
  личность и оказывается в двух сетях ([CONTAINERS.ru.md](CONTAINERS.ru.md) I1).
  К тому же они растут как программы × зоны: около сотни на реальном рабочем
  столе.
- **Один перехваченный ярлык остаётся.** Это и есть механизм «контейнеров по
  умолчанию»: всё, что запускает программу через её запись, идёт через пикер, и
  пикер без диалога находит контейнер, как только программа назначена.
- **Где клоны действительно нужны, их заменяют ярлыки контейнеров**: только для
  программы, назначенной двум и более контейнерам («Firefox — work», «Firefox —
  personal»), по назначениям, а не произведением. `Exec=vpn-zone launch <id>
  --container <c>`; `MimeType` — только у основной записи программы.

Шаги:

1. **сейчас**: `vpn-zone mode per-zone|both`, `vpn-zone sync` в этих режимах и
   настройки GUI говорят, что режим устарел и почему; ничего не удаляется;
2. с моделью контейнеров (этап 1): ярлыки контейнеров; GUI перестаёт
   предлагать `per-zone`;
3. когда вид по контейнерам в ходу: генерация per-zone убирается, с записью в
   CHANGELOG и миграцией, удаляющей наши клоны (на них наш маркер).
